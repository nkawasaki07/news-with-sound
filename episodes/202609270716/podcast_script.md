### トピック2: Cloudflare、HTTPの`Vary`ヘッダーに正式対応 — キャッシュ分散を設定で制御
📅 2026年9月22日公開（出典: Cloudflare Blog）

`Vary` は「同一URLでもリクエスト内容によって応答が変わる」ことをキャッシュに伝えるヘッダーだが、**生の値をそのまま比較すると些細な差異でキャッシュエントリが爆発的に分散し、ほとんど再利用されない**という長年の問題があった。Cloudflareの調査では**約3,000サイトが4つ以上のフィールドで変動**し、**最大47フィールド**で変動するサイトも存在した。

今回 **Cache Rules に3つの処理方式**が導入された。

- **normalize** — `Accept` / `Accept-Language` などを正規化し、**等価なリクエストでキャッシュを共有**
- **passthrough** — 完全な値を保持し、**厳密な差異を区別**
- **bypass** — Cookie のような**高カーディナリティのヘッダーをキャッシュ対象外**に

これまで**カスタムキャッシュキーや Worker 側のロジックで自作していた処理を、宣言的な設定に置き換えられる**のが実務上のメリット。

### 💻 トピック4: Rust公式が警告 — Miri出力をキャッシュするとCIのシークレットが漏洩
📅 2026年9月21日公開（出典: Rust Blog / Rust Security Response Team）

**Miri は ビルド環境を再利用するため、すべての環境変数を `target/` ディレクトリに保存する**。一方 GitHub Actions では**メインブランチのキャッシュをプルリクエストから読める設定が一般的**。この2つが重なると、**環境変数で渡したシークレットがキャッシュに永続化され、PR経由で抽出できてしまう**。

**影響を受ける条件（すべてを満たす場合）**

1. CI で `cargo miri` を実行している
2. Miri のステップが**環境変数経由でシークレットにアクセスできる**
3. `target` ディレクトリを **`actions/cache` 等でキャッシュ**している
4. そのキャッシュが**PRから読み込み可能**

**緊急対応**: キャッシュの無効化 / シークレットのスコープを Miri 非実行ステップに限定 / 一時的に Miri を無効化。
**長期対応**: **修正版 Miri への更新**と、**漏洩した可能性のあるシークレットのローテーション**。

Miri の有無にかかわらず、**パブリックキャッシュへ書き込めるジョブにシークレットを渡さない**という原則が改めて強調されている。
