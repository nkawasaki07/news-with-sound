### トピック1: グーグル、Gemini 3.5 Transcribe を正式提供開始
📅 2026年8月26日公開（出典: Gemini API 公式チェンジログ）

グーグルが Gemini API に**音声認識専用モデル2種を正式版（GA）**として追加しました。

- **Gemini 3.5 Transcribe**（`gemini-3.5-transcribe`）— 高精度・低遅延の非ストリーミング型。**85以上の言語**の発話単位での自動判別、**話者分離（スピーカーダイアライゼーション）**、**単語単位のタイムスタンプ**に対応。さらに専門用語や固有名詞を**最大1,000語**まで登録して認識を寄せる**カスタム語彙バイアス**が使えます。
- **Gemini 3.5 Transcribe Live**（`gemini-3.5-transcribe-live`）— Live API 経由の**WebSocket双方向ストリーミング版**。暫定テキストと確定テキストのイベントを逐次返し、スマート文字起こしモードと複数の**VAD（音声区間検出）戦略**を選択可能。

リアルタイム字幕や音声エージェントの実装が、APIひとつで組める段階に来たという内容です。

### トピック2: Next.js が緊急セキュリティリリース、認証不要RCE を2件修正
📅 2026年8月25日公開（出典: Next.js 公式ブログ / The Hacker News）

Next.js が**深刻度クリティカルの脆弱性2件**を修正した **v16.3.3（Active LTS）** と **v15.5.24（Maintenance LTS）** を公開しました。いずれも**未認証のリモートコード実行（RCE）**に至ります。

- **CVE-2026-75604（CVSS 9.0）** — Windows ファイルシステム上でサーバーを動かしている場合の**パストラバーサル**。Pages Router と App Router を併用し、かつ Cache Components 未使用の構成が対象。
- **AVIF 画像最適化の脆弱性（CVSS 9.5）** — sharp が内部で使う **libheif** に起因し、**攻撃者が用意した AVIF 画像を最適化させるだけ**でRCEに到達。修正版では上流の対応が行き渡るまで **AVIF最適化そのものを無効化**するという踏み込んだ措置。

**8月27日時点で悪用の報告はなし**。該当バージョン利用者は速やかな更新が推奨されます。

### 🔒 トピック3: CISA、実環境で悪用中の脆弱性を1日で6件 KEV 追加
📅 2026年8月26日追加 / 8月27日報道（出典: CISA / Infosecurity Magazine）

米CISA が**KEV（実環境で悪用が確認された脆弱性）カタログ**に、8月26日だけで**6件**を追加しました。

**深刻度の高い2件（パッチ期限: 8月29日）**

- **CVE-2026-8452（CVSS 8.8）** — Citrix **NetScaler ADC / NetScaler Gateway** のメモリオーバーフロー。Gateway（SSL VPN・ICA Proxy・CVPN・RDP Proxy）または AAA 仮想サーバー構成時に**予期しない動作やDoS**を招く。修正版は 14.1-72.61 / 13.1-63.18 以降など。
- **CVE-2019-1068（CVSS 8.8）** — **Microsoft SQL Server のRCE**。2019年公表・**パッチ提供から7年**が経つが、いまだ未更新環境が狙われ続けている。

**残る4件（パッチ期限: 9月9日）** はいずれも数年前の古い脆弱性 — CVE-2015-3246（Red Hat libuser）、CVE-2015-5287（ABRT 権限昇格）、CVE-2021-23758（Ajax.NET デシリアライズ）、CVE-2022-0995（Linuxカーネル境界外書き込み）。**放置された古い穴こそが現実の侵入口**という実態を示す内容です。

### 🔒 トピック4: Linux Foundation、AIエージェントの挙動を証明する新標準「TRACE」
📅 2026年8月25日発表 / 8月26日報道（出典: Linux Foundation / Infosecurity Magazine）

AIエージェントには「**実際に何をしたのかを後から証明できない**」という構造的な課題があります。Linux Foundation はこれに対し、オープン標準 **TRACE（Trust, Runtime Attestation and Compliance Evidence）** を発表しました。

- 開発は秘密計算ベンダー **OPAQUE**、**AMD・Intel・Microsoft・TII** が支援。仕様のガバナンスは Linux Foundation がベンダー中立で担当。
- IETF/IRTF の既存標準を組み合わせる設計 — **RFC 9711（EAT）** をクレームの封筒に、**RFC 9334（RATS）** で attester / verifier / relying-party の役割を定義、**SCITT ドラフト**で透明性台帳へアンカリング。
- **実行環境・実行したソフトウェア・適用ポリシー・データ分類・使用ツール**を紐づけた、**ハードウェア裏付けの暗号的検証が可能な記録**を生成。AMD の **SEV**（VMメモリを暗号化しホストや管理者からも読めなくする技術）を利用。
- 生成される証跡はクラウド事業者をまたいで**ポータブル**。いわば**AIエージェントの行動に対する改ざん困難なレシート**。
- 参照ライブラリは6月の初公開から**10週間で約135,000 PyPIダウンロード**と、開発者の関心も高い状況です。
