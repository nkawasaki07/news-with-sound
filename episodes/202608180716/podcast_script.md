### トピック1: Claudeが生成した文章に不可視ウォーターマークを埋め込み開始
📅 2026年8月11日公開（出典: Fortune / Forbes / Gizmodo）

アンソロピックが、**2026年8月2日以降にリリースされたClaudeモデルの生成テキスト全体**に、目に見えないウォーターマーク（電子透かし）を埋め込むと公表しました。

- 隠し文字を挿入するのではなく、**モデルの単語選択にわずかな偏りを持たせる**方式。十分な長さのテキストがあれば機械的に検出可能で、コピー＆ペーストしても透かしは付いて回る
- 画像・SVGなどのファイルには、**C2PA標準に沿った署名付き来歴メタデータ**を付与
- 背景は**EU AI法 第50条の透明性義務**。グローバルに適用され、**オプトアウトは提供されない**
- 限界も明示されており、**大幅な編集・言い換え・翻訳・他の文章との混在で信号は失われる**。短い文章では検出に必要な量に達しない

検出ツールと詳細ドキュメントは今後提供予定とされています。

### トピック2: Zed開発チームがエージェント協働環境「Delta」を発表
📅 2026年8月12日発表（出典: Zed公式ブログ / Publickey 8月17日）

高速コードエディタ「Zed」の開発チームが、**人間とAIエージェントの全対話とコード変更履歴をコンテキストとして保存・共有する**コラボレーションツール「Delta」を発表しました。

- チャット上で仕様を議論し、**エージェントへの指示を共同編集**、出力とコード変更結果までが同じ場所に残る
- 狙いは「**そのコードがなぜ、どんなプロンプトで生まれたのか**」を後から追えるようにすること
- 基盤は**CRDT（Conflict-free Replicated Data Type）を用いたDeltaDB**。複数人・複数エージェントの同時編集でも矛盾が起きない
- **RustクライアントをWebAssemblyにコンパイル**し、WebGL描画でブラウザからもネイティブ相当の体験。**Claude Codeのターミナルセッションとのリアルタイム同期**も予定
- Zed本体とは別アプリ。「既存エディタに新機能として組み込むのではなく、DBとアプリが互いをかたち作れるように」との判断
- 現在は**プライベートベータの招待を配布開始**した段階

### トピック3: Visual Studio Code 1.133、内蔵ブラウザがローカルHTMLを自動リロード
📅 2026年8月12日リリース（出典: Visual Studio Code公式 / Publickey 8月18日）

マイクロソフトが**VS Code 1.133**を正式リリース。Web開発ワークフローに直結する更新が入りました。

- **内蔵ブラウザのローカルHTML自動リロード**：`Refresh Automatically` 設定により、HTMLファイルの変更が即座に画面へ反映。**エージェントが書き換えた結果もその場で確認できる**
- **チャットのスティッキースクロール**（`chat.stickyscroll.enabled`）：長い会話でも、いま表示中のやり取りが何番目のプロンプトに属するかを上部に固定表示。前後のプロンプトへ矢印でジャンプ可能
- **CopilotとAnthropicのモデルを混在可能に**：ターンごとにモデルを切り替えられる。Anthropic側はAPIキー、Copilot側はサブスクリプションを使用

### 🛠 トピック4: OpenTelemetryのエンティティイベント、「何が存在するか」を観測データにする
📅 2026年8月14日公開（出典: OpenTelemetry公式ブログ）

メトリクス・ログ・トレースは「システムが**どう振る舞ったか**」を教えてくれますが、「**いまどんなホストやサービスが存在しているか**」という生きた構成情報は、オープンな可観測性スタックの死角でした。

- Entities SIG発の**エンティティイベント**がその穴を埋める仕組み。仕様は**v1.58.0（2026-06-22）で正式にシップ済み**
- 実体は**OTLPログレコード**に `otel.entity.event.type: entity_state`（観測）／`entity_delete`（削除）といった型を付けたイベントストリーム
- 記事が示す受信側の設計は**イベントソーシング**：まず永続ログへ追記し、そこから**バイテンポラルなエンティティ・グラフ**を再構築する。構成変化を時間軸で遡れる
- 再構築したグラフを**GraphQL API**と**MCPサーバー**の両方で公開し、**AIアシスタントから直接インベントリを問い合わせられる**点が実用上のハイライト
- 単独のインベントリではなく、メトリクス・ログ・トレースを**横断する結合キー**として効かせるのが本来の狙い

## まとめ

生成AI側では、出力に印を付ける**ウォーターマーク**と、開発の過程そのものを記録する**Delta**という、どちらも「AIが作ったものの来歴を残す」動きが同じ週に並びました。開発現場側では**VS Codeの自動リロード**でエージェントの作業結果をすぐ目視できる導線が整い、インフラ側では**エンティティイベント**によって構成情報が観測可能なデータとして扱われ始めています。作る・確かめる・記録するの三つが、少しずつ地続きになってきた一週間でした。
