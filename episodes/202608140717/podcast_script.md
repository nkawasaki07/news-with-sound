### トピック2: Cloudflareが「Agents Week」の成果を総括、エージェント専用ブラウザ「Kitesurf」も

📅 2026年8月10日公開（出典: Cloudflare Blog）

Cloudflareが1週間にわたる **Agents Week** の発表内容を総括。開発者向けの主なものは以下です。

- **Kitesurf** — AIエージェント専用に設計された新ブラウザ。**Cloudflare Workers の V8 isolate 上で動作**し、ピクセル単位の正確なレンダリングを捨てる代わりに**メモリとCPU消費を大幅に削減**
- **Workers RPC が Python ⇄ JavaScript 間で相互呼び出し可能に** — 混在言語プロジェクトが組みやすく
- **Workers / Containers が inbound TCP接続と gRPC に対応** — 音声AIバックエンドなどリアルタイム用途向け
- **MCPv2** — MCPサポートの書き直し版。エージェントアプリのデプロイとスケールを簡素化
- **@cloudflare/computer** — 用途に応じて実行環境を自動選択するエージェント向けランタイム
- ローカル開発への分散トレーシング導入、AI Search、Cloudflare Wallets など

> 💡 **V8 isolate** … ブラウザやWorkersで使われる軽量なJavaScript実行環境。コンテナより起動が速くメモリ消費が小さい。

### 🔒 トピック3: Windows Defenderの新ゼロデイ「ShieldBreak」PoC公開、SYSTEM権限を奪取

📅 2026年8月12日公開（出典: The Hacker News / BleepingComputer / SecurityWeek）

**Chaotic Eclipse**（別名 Nightmare-Eclipse）を名乗る研究者が、Microsoft Defenderの新ゼロデイ **ShieldBreak** の実証コード（PoC）を公開しました。

これは既存の **CVE-2026-50656（通称 RoguePlanet、CVSS 7.8）のパッチバイパス**にあたります。

**攻撃の流れ:**

1. 偽のクラウドプロバイダーを登録し、細工したプレースホルダーファイルを関連付ける
2. **CLFS（Common Log File System）のログ操作**と**オブジェクトマネージャのシンボリックリンク**を組み合わせる
3. Defenderのスキャン処理に**正規のシステムDLLをロックさせる**
4. その裏で悪意あるファイルへ差し替え → **SYSTEM権限のシェルを取得**

**Windows 11 25H2（Canaryチャンネル含む）と Windows Server 2025 で成功率100%** と報告。Windows 10系は未対応ながら同様に脆弱とされています。**修正パッチは未提供**です。

### 🔒 トピック4: GitHubがnpmとActionsの既定値を厳格化、「待機期間 vs 署名」で議論

📅 2026年8月8日公開（出典: InfoQ / GitHub Blog）

GitHubが2026年3月〜7月に投入したサプライチェーン攻撃対策を総括。重要なのは、**オプション追加ではなく「既定値そのもの」を変えた項目が多い**点です。

**初期侵害の遮断:**

- npmで影響の大きいアカウントがメールアドレス変更または2FAリカバリーコードを使うと、**72時間の読み取り専用モード**へ
- `actions/checkout` の既定動作を変更し、悪用されやすいトリガーでは**信頼できないフォークのコードをチェックアウトしない**（旧バージョン固定のパイプラインにもバックポート）

**権限昇格・流出・伝播の抑止:**

- ワークフロー実行ポリシー（誰が・どのトリガーで起動できるか）
- 信頼できないトリガーでは**Actionsキャッシュを読み取り専用**に
- npm trusted publishing が CircleCI に対応、**staged publishing** で追加承認＋2FAを必須化
- **npm v12 でインストールスクリプトを既定無効化**、git/リモートURL経由の依存も無効に
- Dependabot のバージョン更新は**3日待ってからPRを作成**

一方でコミュニティの反応は割れています。「72時間は病気や旅行を考えると短すぎる」という声、「期限切れドメインを8ドルで買えば約7万社に到達できる状況では待機期間は無意味」という指摘、そして**「10年間拒否され続けてきた作者側のパッケージ署名を導入すべき」**という根本的な批判が目立ちました。反論としては「Linuxディストリが安全なのは署名そのものより push権限を持つ人が少なく時間差があるからだ」という意見も出ています。

## まとめ

生成AIでは、**Grok 4.6が価格据え置きのまま最上位クラスに並び**、コスト効率が競争軸として一層鮮明になりました。

Web開発では、Cloudflareがエージェント前提のブラウザ・ランタイム・RPCを一気に投入し、**開発基盤そのものの前提が書き換えられつつある**ことが見えてきます。

セキュリティは対照的な2本。**パッチをすり抜けるShieldBreak**は「修正済み」がゴールではないことを、**GitHubの既定値変更**は「守り方の設計思想」そのものが未解決の論点であることを示しています。技術的な穴を塞ぐことと、運用の前提をどう置くかは別問題だ、というわけですね。
