### トピック1: Anthropic、Python SDK v1.0を公開 — HTTP層をhttpx2へ移行、破壊的変更あり
📅 2026年8月20日公開（出典: Claude Developer Platform リリースノート）

AnthropicがClaude開発者プラットフォーム向け**Python SDKのv1.0**を公開。最大の変更は、HTTP層が`httpx`から**`httpx2`（メンテナンスが継続されているAPI互換フォーク）**へ移行した点です。カスタムの`http_client`・`Timeout`・トランスポートを組んでいる場合は`httpx2`側の型で作り直す必要があり、`httpx`にパッチを当てるトレース／モック系ライブラリに依存しているなら起動時に**`httpx2.alias_httpx()`**を呼ぶことで互換を維持できます。

あわせて**必要なPythonが3.10以上**に引き上げられ、レガシーなText Completions API、Messagesメソッドの`temperature`/`top_p`/`top_k`、tool runnerのクライアント側`compaction_control`といった**長らく非推奨だったAPIが削除**されました。非同期クライアントでは`.with_raw_response`の結果に`await response.parse()`が必要になり、`AnthropicBedrock`はAWSリージョン未設定時に`us-east-1`へフォールバックせず**エラーを送出**する挙動へ変更。**そのまま上げると壊れる**ため、v1移行ガイドの確認が必須です。

### トピック2: Firefox 154正式リリース — CSSのsibling-index()とtext-box-trimに対応
📅 2026年8月18日公開（出典: MDN Web Docs / Mozilla）

**Firefox 154**が8月18日に正式リリース。CSSでは**`sibling-count()`と`sibling-index()`**をサポートし、「兄弟要素が全部で何個か」「自分は何番目か」を**JavaScriptなしでCSSだけから取得**できるようになりました（インデックスは`0`ではなく**`1`始まり**）。リスト項目ごとに角度や遅延を段階的にずらす演出が、スクリプトを書かずに実現できます。

さらに**`text-box-edge`・`text-box-trim`と短縮記法`text-box`**を追加。テキスト要素のブロック方向にできる余分な空きを、どの辺（over / under / 両方 / なし）からどれだけ削るか指定でき、**複数フォントが混在するブロックの行送りを揃える**用途で効きます。JavaScript側では`Iterator.prototype`に**`includes()` / `join()` / `chunks()` / `windows()`**が追加。`chunks()`は連続した配列チャンクに分割、`windows()`は1要素ずつずれるスライディングウィンドウを返します。

実験扱い（`about:config`で有効化）としては、ベンダー接頭辞なしの`line-clamp`、`text-decoration-inset`のパーセンテージ値、`progress()`関数、Nightly限定のCSS Typed OMが搭載されています。

### 🔒 トピック3: Microsoft Entra IDにCVSS 10.0の脆弱性（CVE-2026-69836）、実環境での悪用も報告
📅 2026年8月21日公開（出典: Help Net Security）

マイクロソフトがクラウドID基盤**Entra ID**（旧Azure Active Directory）の重大なリモートコード実行の脆弱性**CVE-2026-69836**を修正。**CVSSスコアは最大値の10.0**で、Microsoftの主席セキュリティエンジニアRobert Fitzpatrick氏が発見しました。原因はアドバイザリによれば**信頼できないデータのデシリアライズ**で、**未認証の攻撃者がネットワーク越しに任意コードを実行可能**な状態でした。

Entra IDはMicrosoft 365・Azure・連携サードパーティアプリへのログイン検証とアクセス制御を担う中枢です。報道では**実環境での悪用**が確認されたとされます。一方で**利用者側の対応は不要**で、「すでにMicrosoft側で完全に緩和済み。本CVEの公開目的は透明性の確保」と説明されています。ただし**悪用の主体・開始時期・影響組織数・侵入後の行動はいずれも非開示**のままです。

### 🔒 トピック4: AIコーディングエージェントを別アカウントに隔離するOSS「Hazmat」
📅 2026年8月17日公開（出典: Help Net Security）

**Hazmat**は、AIコーディングエージェントを**自分のマシン上の別ユーザーアカウント**で実行するオープンソースツール。Claude Code、Codex、OpenCode、Cursor Agentなど主要ハーネスに加え、自作スクリプトもラップできます。

通常起動したエージェントは**自分と同じ権限**で動くため、**SSH鍵・クラウド認証情報・ホーム配下に蓄積した設定**をすべて読めてしまいます。Hazmatはエージェント専用のホームを与え、**指定したプロジェクトディレクトリのみを共有**。起動前に1コマンドで、書き込み可能ディレクトリ／読み取り専用パス／ネットワーク到達可否／事前バックアップの有無という**セッションの条件を一覧表示**します。macOSでは「プロジェクトのバックアップ → セッション単位のサンドボックスポリシー生成 → エージェントアカウントへ切替 → ハーネス起動」の順に実行され、その時点でファイアウォールルールが適用済み。Linuxはネイティブ動作、Apple container基盤のバックエンドは実験的フラグ扱いです。

コードの**約5.5%は形式仕様記述言語TLA+**で書かれ、隔離モデルを機械検証したとしています。ただし**検証されたのは設計モデルであって、配布されるGoバイナリの正しさは別問題**である点には留意が必要です。GitHubで無償公開されています。

## まとめ

開発ツールの**土台が静かに入れ替わりつつある**一日でした。AnthropicのPython SDKはHTTP層ごと刷新され非推奨APIを一掃、Firefox 154はこれまでJavaScriptに頼っていた兄弟要素カウントやテキスト余白調整を**CSSの標準機能として取り込み**ました。

一方、Entra IDのCVSS 10.0は**認証基盤という最深部の部品でさえ壊れうる**ことを示し、Hazmatは**AIエージェントに自分と同じ権限を渡し続けてよいのか**という問いを突きつけています。便利さと権限は、常にセットで検討すべき対象です。
