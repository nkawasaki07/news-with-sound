### トピック2: WebMCPはChromeオリジントライアル進行中、しかし採用率はほぼゼロ
📅 2026年7月23日公開（出典: Spronta リサーチレポート）

**WebMCP**は、ページ側がJavaScriptで型付きツール（名前・自然言語の説明・JSONスキーマ）を登録し、ブラウザ経由でAIエージェントに直接呼び出させる提案仕様です。DOM解析やスクリーンショット操作に頼らずに済むのが利点で、W3C Web Machine Learning CGのドラフトとしてGoogleとMicrosoftのエンジニアが共同編集しています。

現状は**供給と需要がちぐはぐ**。Chromeは**149〜156でオリジントライアル**を実施中、Edgeはフラグ付きで実装済みですが、**ツールを実際に呼び出す主要AIエージェントはまだゼロ**、登録サイトもほぼ皆無です。加えて**7月21日のドラフトでAPIが `navigator.modelContext` から `document.modelContext` へ移動**し、Chrome 150で旧位置が非推奨に。今実装するならフォールバックが必須です。なおLighthouseには5月からagentic-browsing監査カテゴリが入っており、これが警告に昇格した時が普及の転換点との見方が示されています。

### 🔒 トピック3: Arista VeloCloud OrchestratorにCVSS 10.0のゼロデイ、CISAが3日以内の適用を指示
📅 2026年7月27日公開（出典: SecurityWeek / CISA）

SD-WAN管理製品 **Arista VeloCloud Orchestrator（オンプレミス版）**に、**CVSS 10.0**の**OSコマンドインジェクション脆弱性 CVE-2026-16812** が公表されました。**認証不要**のリモート攻撃者が、本来は内部専用の特権機能に到達でき、システムの完全掌握につながります。

すでに**実環境で悪用されているゼロデイ**で、米CISAは**7月27日にKEV（既知悪用脆弱性）カタログへ追加**し、BOD 26-04に基づき連邦機関へ**3日以内**という異例の短期パッチ期限を課しました。修正版は **5.2.3.14 / 6.1.3.4 / 6.4.2.4 / 7.0.0.1**。Hosted版・Dedicated版は公開前に修正済み、VeloCloud Gateway / Edge は影響なしとされています。

### 🔒 トピック4: npm、公開時マルウェアスキャンを開始。デュアルユース申告と2FA公開が必須に
📅 2026年7月28日公開（出典: GitHub Changelog）

npmレジストリで、**新規公開パッケージがインストール可能になる前に自動マルウェアスキャン**を受ける仕組みが導入されました。結果に応じて「通常公開」「手動レビュー保留」「ブロック」に分岐し、**公開からインストール可能になるまで通常5分程度**（ピーク時は15分以上）の遅延が発生します。公開直後のインストールを前提としたCIには修正が必要です。スキャン中も `npm dist-tag` は動作しますが、`npm deprecate` / `npm unpublish` は使えません。

あわせて、セキュリティツールなど**マルウェアに似た正当な機能（デュアルユース）**を持つパッケージ向けに、`package.json` の **`contentPolicy` フィールド**とパッケージ直下の **`DISCLOSURE` ファイル**による申告が導入されました。申告したパッケージは **2FAを強制する方法（trusted publishing / OIDC、対話セッション、staged publishing）でのみ公開可能**で、以後のバージョンで申告を削除するとpublishが拒否されます。

## まとめ

開発ツール側では、VS Codeが**エージェントとの共同作業を前提とした画面設計**へ本格的に踏み込みました。Web標準側では、**WebMCP**が「仕様とブラウザは揃ったが呼び出す側がいない」というブートストラップ問題の真っ只中にあります。

一方セキュリティは守りの両輪が動いた週でした。**CVSS 10.0のゼロデイ（CVE-2026-16812）**は3日以内の適用が求められる緊急案件、**npmの公開時スキャンとデュアルユース申告**はサプライチェーン攻撃への構造的な対策です。AIエージェントが実際にコードとパッケージを触る時代だからこそ、**供給元の検証**が効いてきます。
