### トピック2: SvelteKit 3.0プレビューでAPI再編が進行、Svelte 8月アップデート
📅 2026年8月1日公開（出典: Svelte 公式ブログ）

Svelteの月次アップデートで、次期メジャー **SvelteKit 3.0.0 プレビュー**の大きなAPI変更が明らかになりました。

- **浅いルーティング（shallow routing）が `goto` の新 `state` オプションに統合**され、`pushState` / `replaceState` を置き換え（`persistState: true` でリロード後も保持）
- `goto` の `noScroll` と `keepFocus` は**単一の `reset` オプションに集約**
- `invalidateAll` は非推奨となり **`refreshAll` に置き換え**
- 新モジュール **`$app/manifest`** が `immutable` / `assets` / `prerendered` / `routes` を公開し、実行時にビルド結果を参照可能に
- `$service-worker` は **`$app/service-worker`** へ移行、サービスワーカー内でも `$app/paths` が使用可能
- **新デプロイの検知**がタブのフォーカス時・可視性変更時にも走るように（デフォルトで `version.poll`）
- 安定版側では、リモートフォームに**送信の瞬間を検知できる `submitted` プロパティ**が追加

なお `error(status, {...})` は非推奨となり、**エラーメッセージが必須**の形式へ変わります。

### 🔒 トピック3: Terraform MCP ServerにCVSS 10.0の認証バイパス、CVE-2026-16498
📅 2026年8月5日公開（出典: The Hacker News / HashiCorp Discuss HCSEC-2026-23）

HashiCorpの **Terraform MCP Server** に、**CVSS 満点の10.0**という認証バイパス脆弱性が公開されました。

- 問題は**ステートレスHTTPモード**。基盤となるMCPライブラリが**セッション固有IDを割り当てていなかった**ため、認証情報キャッシュが利用者を区別できなかった
- 結果として、**ある利用者のTerraformトークンが後続の別利用者のリクエストで再利用される**（クロステナントの資格情報再利用）
- streamable-HTTPトランスポートには**他にも3件のクリティカル**（資格情報のリダイレクト、認可バイパス等）
- 影響範囲は **0.2.1 〜 1.0.0**、**1.1.0 で修正済み**

**共有・マルチユーザー環境では最優先の更新対象**。アップグレード後は**認証情報のローテーションとアクティブセッションの無効化**まで実施、即時更新できない場合は streamable-HTTP の公開を停止し信頼済みネットワークに限定することが推奨されています。

### 🔒 トピック4: Djangoが4件の脆弱性を修正、6.0.8 / 5.2.17 を公開
📅 2026年8月4日公開（出典: Django 公式Weblog / CyberSecurityNews）

Djangoが**セキュリティリリース 6.0.8 と 5.2.17** を公開。main / 6.1 RC / 6.0 / 5.2 の各ブランチが対象で、**4件のCVE**を修正しています。

| CVE | 深刻度 | 内容 |
| --- | --- | --- |
| **CVE-2026-15307** | High | 空間ルックアップで `GDALRaster` 経由のラスタ値を処理する際、ドライバー次第で**サーバー上のファイル書き込み**やDjangoプロセス権限での**ネットワークリクエスト**が発生しうる |
| **CVE-2026-15830** | - | WKT/WKB入力の**ジオメトリコレクションのネストを最大198**に制限 |
| **CVE-2026-15337** | Low | `check_for_language()` が長大な言語コードを大量に処理すると**DoS**。**500文字超はキャッシュ参照前に拒否** |
| **CVE-2026-15920** | Moderate | 管理画面で `URLField` が**スキーム未検証のままリンク描画**され**格納型XSS**。今後は `URLValidator` 検証を通し、不正値はプレーンテキスト表示 |

**Django管理画面を運用しているプロジェクトは早期のアップグレードを推奨**します。
