### トピック1: Cloudflare、AIエージェント専用ランタイム「Cloudflare Computer」を公開
📅 2026年8月7日公開（出典: InfoQ）

Cloudflareが、AIエージェントに**使い捨てコンテナではなく「本物のコンピューターに近い環境」を与えるオープンソースのランタイム**を発表しました。同社は「数億〜数十億の同時エージェントをコンテナだけで支える計算資源は世界に存在しない」と主張しています。

このランタイムでは、処理ごとに**Isolate（軽量実行単位）／コンテナサンドボックス／ブラウザのどれで動かすかをプラットフォーム側が自動選択**します。両者は**SQLiteベースの共有ファイルシステム**で接続され、同じファイルを扱いながら処理を行き来できます。目標は「**コンテナが必要な作業を全体の10%未満に抑えること**」。バックエンドは container projects／isolate shells（just-bash）／isolate JavaScript の3種類。現時点では**早期プレビュー**で、実験・試作向けと位置づけられています。

### トピック2: npmの「Staged Publishing（ステージド公開）」がGA、公開前に人の承認を必須化
📅 2026年8月7日公開（出典: InfoQ）

GitHubが管理するnpmが、**公開したバージョンが即座にはインストール可能にならない仕組み**を一般提供開始しました。publish時にtarballは**承認待ちキュー**に入り、メンテナーが**2要素認証チャレンジを通して承認**して初めてレジストリに反映されます。

ポイントは、**ステージング自体には2FAが不要**なこと。非対話的なCIパイプラインはそのまま動き、「人がその場にいる証明」は承認ステップへ移動します。

- コマンド: `npm stage publish` / `list` / `view` / `approve` / `reject`
- 要件: **npm CLI 11.15.0以上、Node 22.14.0以上**（パッケージが既にレジストリに存在すること）
- 併せて `--allow-file` `--allow-remote` `--allow-directory` を追加。`--allow-git` は**v12で既定 `none`**へ
- **pnpm 11.3** が `pnpm stage` を、Yarnも `yarn npm stage list` を実装済み

背景にはShai-Huludワームなど**サプライチェーン攻撃の連続**があります。一方HNでは「絆創膏に過ぎない」との批判や、「メンテナーが実際に使わなければ意味がない」という指摘も出ています。

### 💻 トピック3: Vercel Labs、AIエージェントのための実験的システム言語「Zero」を公開
📅 2026年8月6日公開（出典: InfoQ）

**「コンパイラ出力の第一の読者はもう人間ではなくAIエージェントだ」**という前提で設計された実験的システムプログラミング言語です。拡張子は `.0`、Apache 2.0ライセンス、**v0.3.4**、GitHubスター**5,200超**。Linux/macOS/Windows向けネイティブバイナリを生成し、hello worldは**16.2KiB／ビルド1ミリ秒**と報告されています。

最大の特徴は**ツールチェーン契約**です。

- 全サブコマンドが `--json` と**単一の診断スキーマ**を共有
- エラーは `NAM003` のような**安定コード**と `declare-missing-symbol` 等の**型付き修復メタデータ**を伴う
- `zero fix --plan --json` が**機械可読な修復プラン**を返し、エージェントは受入／編集／拒否を選べる
- 外部I/Oを行う関数は **World ケイパビリティ**の受け取りをコンパイラが強制。**シグネチャだけでネットワーク・ファイル・標準出力に触るか判別可能**

v0.3.0では**グラフファースト**が標準に。バイナリの `zero.graph` ストアがコンパイラ入力となり、`.0` ファイルは人間向けの投影に格下げされました。**v0.3.2で `zero import` が約12倍高速化**。ただしHNでは「構造化エラーは何十年も前からある」との冷ややかな声もあり、評価は分かれています。**破壊的変更を前提とした実験段階**である点に注意が必要です。

## まとめ

本日は**AIエージェントを動かす「土台」**の話が目立ちました。Cloudflareはエージェントに専用のコンピューターを与え、Vercelはエージェントが読み書きしやすい**言語そのもの**を作る。アプローチは正反対ですが、いずれも**エージェントを一人前の書き手として扱う**という前提を共有しています。

対照的なのがnpmのStaged Publishingです。**自動化が進むほど、最後に人の目を一度だけ挟む価値が上がる**という逆方向の答えでした。速さと安全のバランスをどこで取るか——それぞれの立場が鮮明に出た一日と言えます。
