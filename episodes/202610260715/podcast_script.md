Moonshot AIが新モデル**Kimi K3.1 Pro**を公開。Kimiアプリと API で利用できます。

- **総約2.8兆／アクティブ約1040億パラメーターのMoE**、コンテキスト**約100万トークン**、画像・動画入力対応

- **推論は常時オン**、`reasoning_effort` は low／high／max（既定max）。**temperature 1.0・top_p 0.95固定**で他の値はエラー

ベンチマーク（Terminal-Bench 4.0で65.7%など）は**Moonshot自身の測定**で、第三者検証はまだです。

### トピック2: Chrome 156安定版、CSSのrandom()やIndexedDBのSQLite化
📅 2026年10月20日公開（出典: Chrome Geek、GIGAZINE）

- **CSS `random()`**: 範囲内の乱数をCSSだけで生成。キーで値を要素間・プロパティ間で共有可能
- **ナビゲーション元の擬似クラス**: 遷移を開始したリンク・ボタン・フォームを選択でき、View Transitionsの演出に便利
- **単一軸スクロールコンテナ**と `scroll-snap-type: pair`
- **失敗したJSモジュール読み込みがキャッシュされなくなり**、`import()` で再試行可能
- WebTransportでカスタムリクエストヘッダー送信・レスポンスヘッダー取得
- **IndexedDBの保存方式が新規データからSQLiteに**（APIは不変、既存データは移行されず）
- `fencedframe` 要素と `window.fence` は機能停止、**Chrome 157で削除予定**

### 🔒 トピック3: 認証局eMudhraの中間CA秘密鍵が復元可能に、pip・uvなど開発ツールに修正版
📅 2026年10月22日公開（出典: gihyo.jp）

eMudhraの**中間CA証明書8件**（TLS用6、コード署名用2）で、**公開証明書から秘密鍵を復元できる**ことが判明。鍵生成工程の不備で弱い鍵が作られていたとされます。

- 悪用されれば**任意ドメインの偽HTTPS証明書**や**不正な署名付きソフトウェア**が成立し得る
- Firefox・Chromeは10/17にブロック済み。Mozillaは「emSign ECC Root CA - G3」をNSSから除外、Chromeも10/27に除外予定
- **ブラウザー外のツールは独自の証明書バンドルを持つため更新が必要**
  - Python: **certifi 2026.10.19／pip 26.2.2／uv 0.13.4**以降、Python 3.15.1・3.14.9・3.13.17
  - Go 1.27.3／1.26.10、Node.js 22.23.4／24.22.1／26.12.1、rustls-webpki 0.103.16、OpenJDK（CVE-2026-91403）など

**仮想環境ごとの更新とコンテナイメージの再ビルド**を。証明書エラーが出ても**検証を無効化して回避しない**こと。

### 🔒 トピック4: PHP、緊急パッチの2日後に未修正の別のRCEリスク（CVE-2026-115560）を公表
📅 2026年10月23日公開（出典: The Hacker News）

10/21に修正されたPHP2Shell（CVE-2026-109618／109619）とは**別の脆弱性**で、**8.5.12／8.4.27／8.3.36／8.2.35でも未修正**です。

- 条件: `session.serialize_handler` を設定で `php_binary` か `php_serialize` にし、**`session_start()` 前に `ini_set()` で `php` に変更**しているアプリ、かつ**セッションのアップロード進捗機能が有効**
- PHPは発生可能性を低いと評価、影響バージョンやスコアは未公表、**悪用報告なし**
- 修正は**次回の定期リリース**で。それまでは **`session.upload_progress.enabled=0`** を推奨（PHP2Shell対策で設定済みなら追加対応不要）

## まとめ

生成AIでは、**Kimi K3.1 Pro**が低価格・100万トークン文脈で登場し、11月4日までの重み公開が予告されました。Webでは**Chrome 156**でCSS `random()` などが安定版に。セキュリティでは、**eMudhraの鍵問題は自分のサイトで使っていなくても依存ツール経由で影響し得る**ため、pip・certifi・uvや各言語ランタイムの更新を優先しましょう。PHPは**アップロード進捗機能の無効化**が当面の緩和策です。
